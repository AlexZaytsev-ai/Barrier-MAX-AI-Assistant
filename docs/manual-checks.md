# Ручная проверка

## Базовый публичный экспорт

Эта таблица относится к `workflow/barrier-max.public.json` — ранней версии без актуального меню, сводки и обработчика ошибок. Отметки о запуске с новыми credentials в отдельной среде отсутствуют.

| Сценарий | Что проверить |
| --- | --- |
| Обычный вопрос о дверях | Ответ приходит в личный чат; пара user/assistant сохраняется в PostgreSQL. |
| Уточнение с учётом истории | Модель получает предыдущие сообщения в хронологическом порядке; не начинает консультацию заново. |
| «Позовите сотрудника» | В группу приходит запрос с ID клиента и историей; режим меняется на waiting; покупатель получает подтверждение передачи. |
| Сообщение в waiting | Сообщение пересылается в группу и сохраняется; ИИ молчит. |
| Reply сотрудника на сообщение бота | Ответ приходит нужному покупателю; режим становится human; текст сохраняется в истории с пометкой сотрудника. |
| Сообщение покупателя в human | Сотрудники получают сообщение; ИИ не отвечает. |
| Обычный текст сотрудника в группе | Покупатель не получает сообщение без Reply. |
| Reply на сообщение другого человека | Проверка автора исходного сообщения отклоняет ответ. |
| Reply без текста или ID покупателя | Ветка отправки покупателю не выполняется. |
| «Вернуться к ИИ» | Режим становится ai; следующее сообщение обрабатывает модель. |
| Поздний Reply после возврата к ИИ | Проверить доставку, итоговый режим и одновременные события отдельно. |
| Запрос на замер или установку | Обращение передаётся сотруднику; дата и время не объявляются подтверждёнными без его ответа. |
| Посторонняя тема | Бот возвращает разговор к дверям и услугам магазина. |
| Наличие конкретной модели | Бот не выдумывает остатки и предлагает проверку сотрудником. |
| Неверный секрет webhook | Входящий запрос не должен запускать рабочую ветку. |

## Текущая рабочая версия

Проверки ниже относятся к настроенному боту после обновления 5–8 октября 2026 года. Они не означают, что новые возможности входят в ранний публичный экспорт.

| Сценарий | Результат или ожидаемое поведение | Проверка |
| --- | --- | --- |
| Запуск через «Начать» | Приходят приветствие и меню из шести кнопок. | Проверено вручную в настроенной среде. |
| «Меню» и четыре информационных раздела | Разделы открываются, навигация работает. | Проверено вручную в настроенной среде. |
| Подписи на телефоне | Все шесть коротких подписей отображаются полностью. | Проверено вручную в настроенной среде. |
| Передача сотруднику | В группу приходит сводка обращения с ID чата. | Проверено вручную в настроенной среде. |
| Изменённый бюджет | Сводка использует последний бюджет и сохраняет пожелания; повторяющиеся магазинные контакты исключены. | Проверено вручную в настроенной среде. |
| Reply продавца на сводку | Ответ доставляется нужному покупателю, режим меняется на human. | Проверено вручную в настроенной среде. |
| «Спросить ИИ» после сотрудника | Режим становится ai; история не удаляется. | Проверено вручную в настроенной среде. |
| Тест HTTP 429 через рабочий webhook | После неудачных попыток автоматически приходит личное уведомление с workflow, нодой, ошибкой и ссылкой. | Проверено вручную в настроенной среде. |
| Меню и раздел услуг в waiting/human | Открываются без изменения режима; обычные сообщения продолжают идти сотрудникам. | Проверить отдельно в каждом режиме. |
| Возврат из раздела услуг | «Сотрудник» и «Меню» ведут в правильные ветки. | Проверить для каждого раздела. |
| Запоздалый Reply и параллельные события | Зафиксировать порядок сообщений и итоговый режим. | Отдельная проверка; гарантия порядка не заявляется. |
| Ссылки с сайта и QR | Открывают нужного MAX-бота на телефоне и компьютере. | Проверить точки входа отдельно. |

Обработчик ошибок проверяется автоматическим запуском через рабочий webhook. Ручной запуск кнопкой Execute Workflow не проверяет срабатывание Error Trigger. Тестовый workflow с искусственной ошибкой после проверки следует отключить.

Дополнительно проверяются недоступность PostgreSQL, ошибки OpenAI/MAX, повторная доставка событий и параллельные сообщения. Retry настроен для конкретной ноды ответа покупателю в рабочей среде; дедупликация, сериализация событий и повторение всех API-запросов не заявляются.

## Обратная связь заказчика

Нужны наблюдения по удобству меню, точности условий услуг и достаточности сводки продавцу. Для замечания фиксируются сценарий, фактический результат и ожидаемое поведение. Влияние на продажи и нагрузку сотрудников пока не измерено.
