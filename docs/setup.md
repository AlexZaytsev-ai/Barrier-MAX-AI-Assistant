# Настройка публичной копии

Этот документ относится к раннему базовому экспорту. Актуальные меню из шести кнопок, сводка обращения и отдельный обработчик ошибок описаны в [README_RU.md](../README_RU.md), но в опубликованный JSON пока не включены.

Используйте отдельные тестовые бот, группу и базу. После импорта workflow требуется настройка; он не предназначен для немедленного включения на рабочем боте.

## Credentials в n8n

| Ноды | Подключение |
| --- | --- |
| Все HTTP Request-ноды `MAX …` | Собственный credential Header Auth для запросов MAX: заголовок `Authorization` со значением токена бота в формате, принятом API вашей среды. |
| `Webhook` | Отдельный credential Header Auth для проверки секрета входящих событий. Он должен совпадать с заголовком, передаваемым вашей подпиской MAX. Не подставляйте токен исходящих запросов автоматически. |
| Все PostgreSQL-ноды | Собственные host, port, database, user и password. |
| `Консультант по дверям` | Собственный OpenAI API credential и доступная модель. |

Имена и значения секретов задаются в credentials n8n. Не записывайте токены в JSON и не коммитьте их в Git.

## Заглушки

| Значение | Где заменить |
| --- | --- |
| `STAFF_CHAT_ID` | Query Parameters → `chat_id` в `MAX — Уведомить о запросе` и `MAX - сообщение покупателя сотруднику`; Right Value условия в `MAX — Группа сотрудников?`. |
| `BOT_USER_ID` | Right Value третьего условия в `MAX — Данные ответа корректны?`. |

ID группы и бота указываются строками. `BOT_USER_ID` — ID самого бота, не сотрудника. Проверьте его по ответу своего API `/me`.

Webhook path публичной копии — `barrier-max-demo`. Настройте подписку MAX на production HTTPS URL этого webhook в своей среде. Активируйте workflow только после назначения credentials и замены заглушек. Не меняйте подписку рабочего бота ради демонстрации.

## База и промпт

`sql/schema.sql` создаёт минимальные таблицы, совместимые с опубликованными запросами. Сессия имеет формат `max:<chat_id>`. При отсутствии строки в `door_chat_modes` workflow использует режим `ai`.

Перед демонстрацией сверьте условия, адреса, телефоны, часы работы и цены в системных сообщениях ноды `Консультант по дверям` с актуальными данными магазина: публичный экспорт предшествует последним бизнес-правкам. Исходящие вызовы используют адрес API из предоставленного экспорта; при переносе проверьте его доступность из своего сервера и TLS-сертификаты.

## Работа сотрудника

Сотрудник отвечает в группе через функцию «Ответить / Reply» на сообщение бота «Запрос сотруднику» или «Сообщение покупателя», содержащее ID чата клиента. Обычное сообщение в группе не отправляется покупателю.

После настройки базовой копии пройдите соответствующие сценарии из [manual-checks.md](manual-checks.md). При сбоях проверяйте executions n8n. В рабочей среде настроены повторные попытки в ноде ответа покупателю и отдельный Error Workflow с личным уведомлением в MAX; в этот экспорт они не входят.
